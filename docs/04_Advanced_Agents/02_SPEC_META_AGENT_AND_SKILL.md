# Meta Agent 与 Meta Skill 设计规范 (Meta Agent & Meta Skill Specification)

`Meta Agent` 和 `Meta Skill` 是 AI-Nexus 系统实现自我迭代与能力扩张的核心驱动机制。它们共同构成了系统的“造物主”层级。

## 1. Meta Agent (全局造物主)

系统内部除了常规的用户映射分身，还存在唯一一个脱离外部 Channel 独立存在的超级实体——**Meta Agent**。

### 1.1 核心特征
*   **唯一性**：全局单例，不服务于普通人类的日常聊天请求。
*   **独立性**：脱离 Telegram、CLI 等外部物理通道存在，由系统内部任务调度或特定事件触发。
*   **最高权限**：全系统唯一被授权挂载并使用所有 `Meta Skill` 的实体。

### 1.2 核心职责
它的主要目标是根据系统的需要，自动调用 Meta Skills 编写、审查并向系统中发布新的能力模块（Skill），以及生成和装配全新的任务分身（Agent）。它是系统实现自我演进与能力层级扩展的中枢神经。

## 2. Meta Skill (元技能)

`Meta Skill` 是一组专供 `Meta Agent` 使用的底层特权技能，用于实现“编写技能”与“生成 Agent”的造物主能力。常规的 Agent 分身被绝对禁止访问这些技能。

### 2.1 五大核心 Meta Skill
根据架构设计，Meta Agent 挂载的五大 `Meta Skill` 包括：

1.  **定义规则 (Rule Definition)**：
    *   读取并理解系统架构规范与技能契约文档。
    *   明确新技能的输入输出 Schema、所需沙箱权限（网络、内存等）及执行边界。
2.  **代码检索与读取 (Code Reading)**：
    *   扫描现有的 `skills/` 目录，检索已有技能的代码实现。
    *   提供上下文参考，避免重复造轮子，保持代码风格统一。
3.  **技能新建与修改 (Skill Authoring)**：
    *   在单体架构内生成、创建或修改 `SKILL.md` 及相关的执行实体（如通过 Rust 源码编译为 `.wasm` 产物）。
    *   处理运行依赖的声明与编译构建。
4.  **沙箱验证 (Sandbox Verification)**：
    *   在严格受控的 `wasmtime` 原生沙箱中对新生成的 Wasm 模块进行 Dry-run 试运行测试。
    *   捕获执行报错，将异常信息反馈给 Meta Agent 进行自我纠正，直到测试通过并最终持久化到 BlockStore 技能库。
5.  **人设生成与装配 (Persona Authoring)**：
    *   根据特定任务需求，动态生成并注册一个拥有独立设定、限定技能白名单的全新 `PersonaDef` (人设模版)，并为其打上如 `Tier-1-Logic` 的算力标签。当请求来临时再基于该模版实例化 Agent。
    *   定义并编排多个 Persona 之间的协作拓扑与通信链路（如建立专门执行某项长期任务的 Sub-Persona）。

## 3. 自我迭代工作流 (Self-Evolution Workflow)

Meta Agent 利用 Meta Skill 进行能力扩展的标准流转过程如下：

1.  **需求感知**：系统发现当前技能库无法满足某项未知的复杂任务，或者通过后台目标追踪机制触发了扩建需求。
2.  **方案设计**：Meta Agent 构思新技能的结构，使用**定义规则**明确约束边界。
3.  **代码编写**：调用**技能新建与修改**能力，在文件系统中生成对应的元数据与代码脚本。
4.  **安全验证**：触发**沙箱验证**，在一个隔离、资源受限的命名空间沙箱中试运行代码。
5.  **纠错循环**：若验证失败，收集 STDOUT/STDERR 报错，Meta Agent 自主重新修改代码并再次投入验证。
6.  **正式发布**：验证通过后，将技能状态标记为可用，并将其元数据注册进入系统的 GraphRAG 混合检索图谱中，与现有知识节点建立拓扑关联，供常规应用层 Agent 借由联想记忆机制被动召回和使用。
